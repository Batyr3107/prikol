**Серьезность:** 🟡 MEDIUM
**Файлы:** `prisma/schema.prisma`, `prisma/migrations/`

**Проблема:**
После изменения schema (удаление autoincrement), требуется миграция БД. Попытка создать миграцию не удалась из-за сетевых проблем.

**Последствия:**
- При деплое может возникнуть несоответствие схемы и БД

**Решение:**
```bash

npx prisma migrate dev --name remove_user_autoincrement

# Или если в production:
npx prisma migrate deploy
```

**Обходное решение:**
Если схема уже применена, БД будет работать. Но для production лучше создать миграцию.

### 🟡 Средняя #2: Отсутствие проверки санитизации в API
**Серьезность:** 🟡 MEDIUM
**Файл:** `src/server.js:162-163`

**Проблема:**
Хотя мы санитизируем userName, мы не проверяем результат. Если sanitizeText() вернет пустую строку, будет создан пользователь с именем "Аноним" без предупреждения.

**Текущий код:**
```javascript
displayName: sanitizeText(userName) || 'Аноним'
```

**Примечание:**
Это не баг, но может быть улучшено добавлением логирования когда имя санитизируется до пустой строки.

**Решение (опционально):**
```javascript
const safeName = sanitizeText(userName);
if (!safeName && userName) {
  logger.warn(`UserName sanitized to empty for user ${userId}`);
}
data: {
  id: parseInt(userId),
  displayName: safeName || 'Аноним'
}
```
